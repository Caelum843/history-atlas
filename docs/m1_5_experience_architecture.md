## 一个主张：三层不是三个页面，是同一个空间的三个高度

这是整份架构里唯一需要你先同意的判断。

如果世界层、地区层、故事层各自是一个独立页面，那么"世界感"只能靠视觉修辞去伪造——
大图、粒子、渐入，也就是你明确排除的那些。用户在页面之间跳转，每次都是**替换**，
所以每次都要重新建立"我在哪"，世界感永远立不住。

**改为：全站只有一个连续的空间衬底，三层是俯瞰它的三个高度。**

```
世界层   高空   —— 看见整个已知世界，文明是发光的区域场
   ↓ 下降（同一个衬底，镜头连续推进，不是换页）
地区层   中空   —— 降到地中海，对象解析出来：地点、人物、文物、故事
   ↓ 下降
故事层   地面   —— 舞台接管画面，叙事在这个空间里发生
```

由此直接得到四件事，都不用额外发明机制：

| 验收标准 | 由"连续下降"直接满足 |
|---|---|
| 7 · 返回上层时仍知道自己在哪 | 因为从没离开过那个空间，返回是**上升**，不是后退 |
| 1 · 第一屏像进入世界 | 高空视角本身就不是文章版式，不需要靠字号 |
| 2 · 不看文字感到内容规模 | 画面在四边被裁切，可见范围外还有区域场和节点 |
| 8 · 未来能换文明 | 换文明 = 降落到衬底的另一处，框架一行不改 |

### 衬底是"舞台"，不是"地图"

必须说清，否则会和 brief 第 7 节"地图不是所有页面的固定主角"打架。

衬底是一个**空间舞台**，地图只是它的一种模式。故事层里，同一个舞台可以从地图切换成
四维权限面板、元老院席位阵列、制度对照图——空间框架保留，画面内容整个换掉。
M1 建好的 renderer registry 正好就是"舞台有哪些模式"的注册表，
它从文章插图升格为**舞台的视觉层**，不需要重写。

### 世界层不画海岸线

高空视角如果画一张粗糙的世界海岸线，就是在制造虚假精确——而这恰恰是项目反对的。
所以世界层用**经纬网 + 锚在真实坐标上的区域场**：文明是有位置、有边界模糊度的光场，
不是描边的国家。既诚实，也正好把"文明的范围本来就不是线"这件事讲了出来。

海岸线从地区层才出现，并按 `accuracy` 标注。

## 两个参考站真正起作用的机制

只学体验原则，不复制视觉。拆开看，它们各自靠的是一件很具体的事：

**诗云** —— 全部内容**一次性同时可见**。它从不给列表，给一个场；每颗星是一首真诗。
规模感来自"我一眼看到了全部，而每一个都小到需要靠近才能读"。
→ 我们的世界层必须是**场**，不是索引。任何时候都不出现"作品列表"这种东西。

**英雄联盟宇宙** —— 它像一本书，靠两点：
① **无死角互链**：每个英雄页都通向地区、其他人物和故事，你永远撞不到叶子节点；
② **每个地区有自己的视觉身份**。
→ ① 变成一条硬规则：**任何对象浮层至少给出两条去向**，没有终点页。
→ ② 我们已有对应机制：作品/场景主题令牌（`decisions.md` 第二轮）。换文明换一份主题文件。

### 必须先说的风险

诗云有几百首诗，LoL 有一百多个英雄和多年积累的故事。**我们现在有 1 个故事、8 个对象。**

世界感这一轮不可能来自数量。它只能来自三处：

1. 画面在四边被裁切，暗示画外还有；
2. **看得见但进不去的未开放节点**；
3. 每个对象背后那层很深的证据系统——广度不够，用深度补。

第 2 条有个诚实底线：**那些暗节点必须是真的计划中的内容**，不能是为撑场面画的装饰点。
一旦用户点开发现是空的，"世界"立刻塌成一张贴图。
所以本轮的暗节点只放确实在罗马系列规划内的题目（`project_brief_v0.5.md` 第 8 节列出的那些），
并明确标注"未开放"，不假装可点。

这是这个方向最大的风险，也是 M1.5 原型真正要回答的问题：
**在内容还很薄的时候，世界感能不能立住。**

## 三层各自承载什么

### 世界层 `/`

全屏，无文章栏。可见：区域场（罗马世界为主，其余文明为暗场，可感知不可进入）、
故事节点（已开放 / 未开放两种状态）、当前选择状态、探索入口。

时间只显示一个静态状态：**罗马共和国晚期 · 实验内容**。
完整时间系统本阶段不做，通过独立接口接入。

未开放的暗场是刻意的——**"规模远大于当前屏幕"必须由看得见但进不去的东西来证明**，
而不是由一句文案宣称。

### 地区层 `/world/rome-republic/`

卷首页，不是目录。地中海解析出来，对象分三类落位：

- **地点**（罗马、拉文纳、里米尼）落在地图上；
- **人物**（凯撒、庞培）**不落在地图上**——人不是地点，钉在地图上是范畴错误。他们停靠在舞台边缘的人物列；
- **卢比孔河**用虚线无锚点标记——它的位置本来就不可考，数据里 `positionDisputed: true`，视觉必须如实反映。

故事节点：《卢比孔河》已开放，另有若干可感知未开放。
关系连线**默认不显示**，只在选中某个对象时亮起该对象的关系——沿用 M0 审核的"三类关系不同时显示"。

### 故事层 `/story/rubicon/`

全屏舞台。文字是旁白浮层，不是正文栏。滚动推动**同一个舞台**换状态，不是滚过一串区块。
历史对象（人物、地点、法律）在舞台里是可点对象，点开浮层卡片。

本轮只做三个状态：地中海全景 → 意大利北部与行省边界 → 精度耗尽、媒介转换。

## 两层阅读模式

**默认沉浸**：场景、简短旁白、当前时间地点、可进入对象、基础导航。
默认页面**不出现**：renderer 名称、schema 字段、图层 ID、M1/M2 开发状态、大段实验说明、完整来源列表。

**按需研究**：右下角「证据」按钮打开侧边抽屉——论断、来源、争议、替代解释、地图精度、
图像授权、内容状态。抽屉最宽占屏幕 38%，舞台不被顶走，随时可关。

`?debug=1` 才显示 renderer、图层 ID 与开发信息。

M1 建好的严谨系统一项不删，全部移到研究层。

## 数据：加一个轻量世界层，不动现有结构

现有 `schema.ts` 面向作品与论断，需要并列增加一个世界层，**互不侵入**：

```ts
WorldNode {
  id, type: 'region'|'person'|'place'|'event'|'institution'|'artefact'|'story',
  title: I18n, summary?: I18n,
  visual?: string,
  position?: { x, y },        // 世界层布局坐标（不是经纬度）
  related?: string[],
  entry?: string,             // 可进入时的目标路由
  timeContext?: TimeContext,  // 预留，本阶段不使用
}

TimeContext  { from?: number, to?: number, label?: I18n }
Relationship { from, to, type, label: I18n, timeContext? }
```

`position` 与 `entities` 里的 `lon/lat` 分开：世界层是**布局空间**，
地区层才用真实坐标。人物在世界层有 position、没有 lon/lat——这正是"人不是地点"的数据表达。

`timeContext` 与 `Relationship` 本轮**只定义、不使用**，避免时间系统阻塞体验框架。

## 本轮不做

全球时间轴、纪年换算、对象随时间自动出现消失、跨时代关系、复杂历史地图状态、
完整世界史数据、真实地理数据管道（留给 M2）、拍 4–拍 6、3D/WebGL。

## 技术手段

SVG 为主（衬底、区域场、地图、舞台），CSS 负责层次与转场，Canvas 只在需要大量粒度元素时局部使用。
镜头下降复用 M1 已验证的 viewBox 补间思路。保留 `prefers-reduced-motion` 与键盘操作。

## 需要你确认的四点

1. **"三层 = 同一空间的三个高度"** 这个主张成立吗？如果你更想要三个独立场景（各有各的视觉世界、之间靠转场衔接，更接近 LoL 那种"每个地区一套画风"），框架要换一种搭法，现在改成本最低。
2. **世界层用经纬网 + 区域场、不画海岸线** —— 诚实但抽象，可能不如一张世界地图有即时冲击力。接受吗？
3. **人物不落在地图上** —— 数据上正确（人不是地点），但会让地区层的人物列看起来像侧边栏。接受吗？
4. **未开放节点放多少** —— 放得多，世界感强，但都是不能点的暗点；放得少，画面诚实但显空。
   我在构图里按"罗马系列真实规划"放了 7 个暗节点，你看密度合不合适。
