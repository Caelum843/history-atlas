M1.5 历史世界体验框架——执行说明

现有 M1 的 schema、史料校验、来源结构和 renderer registry 继续保留，但“纵向文章 + 插入图表”不作为最终体验方向。

产品目标：建立一个可以探索的历史世界。用户先感受到完整世界，再进入地区、人物和故事；史料系统负责支撑可信度，但不占据默认视觉主体。

本阶段先搭体验框架，暂不完善全球时间轴、复杂历史关系和完整史料。

一、建立三层体验

1. 世界层：全屏世界舞台，显示地区、文明、人物、地点和故事节点。首版只放少量罗马占位内容。
2. 地区层：进入“罗马共和国晚期”，看到主要地点、人物、文物和可进入作品，像一部作品的卷首页，而不是目录。
3. 故事层：进入《卢比孔河》后，以全屏视觉舞台为主体；滚动改变同一舞台的状态，文字以简短旁白出现，不再按“标题—正文—图表”重复排列。

二、两层阅读模式

- 默认沉浸模式：场景、地图、人物、简短旁白和导航。
- 研究模式：通过侧边抽屉查看论断、来源、争议、地图精度和图像授权。
- renderer 名称、图层 ID、M1/M2 状态等仅在 ?debug=1 下显示。

三、先做 60—90 秒最小原型

体验路径：

历史世界 → 罗马共和国晚期 → 《卢比孔河》 → 点击凯撒或地点 → 打开对象卡片 → 打开证据抽屉 → 返回上层。

《卢比孔河》本轮只做三个舞台状态：

1. 前49年的地中海与主要故事节点；
2. 镜头进入意大利北部，出现行省边界和权限信息；
3. 地图因证据不足无法继续精确放大，转换为现代河流影像或占位视觉。

暂不完成全部六拍，也不先建设完整地理数据管道。

四、技术处理

- 保留现有 schema、场景数据、renderer 和校验机制。
- 当前文章式页面保留为开发/研究视图。
- 新建世界层、地区层和沉浸故事壳。
- renderer 应成为舞台中的视觉层，而不是文章插图。
- 世界对象先使用轻量结构：id、type、title、summary、visual、related、entry；timeContext 暂时可选，以后补充完整时间关系。

建议路由：

/                         历史世界
/world/rome-republic/     罗马共和国晚期
/story/rubicon/           沉浸式卢比孔
/dev/scene/rubicon/       当前文章式开发视图

五、执行顺序

1. 先提交世界层、罗马卷、卢比孔故事三张连续静态构图；
2. 等我确认“世界感”和体验方向；
3. 再制作可操作的 M1.5；
4. M1.5 审核通过后再继续 M2 地图数据工作。

验收重点：第一屏像进入世界而不是文章；世界—地区—故事路径清楚；三次滚动真正改变同一舞台；历史对象可以进入；证据系统随时可查但不破坏沉浸；框架未来可以换成其他文明。

不要只通过大图、粒子、字体放大或渐入动画美化现有文章页面。本轮要验证的是“可信度内核能否进入一个有世界感、探索感和章节感的历史体验”。
