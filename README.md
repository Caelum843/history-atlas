# history_atlas —— 互动历史书

跨文明、跨地区、跨时代的互动历史叙事与探索网站。用地图、图像、时间变化、人物关系、制度结构与史料，
让读者看见历史中的空间变化、权力变化和因果联系。罗马史是第一项内容实践，不是主题边界。

## 当前阶段

首轮实验用于验证内容方法、视觉语言与交互框架是否成立。当前已进入 **M1.5 正式体验骨架**：

1. **世界层**以 Natural Earth 真实海陆数据建立空间可信度，不绘制现代国界；
2. **罗马卷**使用独立的暖色石质视觉身份，地图退为一种空间参照；
3. **卢比孔故事**使用全屏三幕叙事舞台，并接入对象互链与证据抽屉；
4. **对象页**保证人物、地点、制度和文献不会成为叶子节点。

后续内容工作继续遵循三项原则：

1. **把卢比孔河场景做透** —— 一个场景的完成度决定方法论是否成立；
2. **尽早跑通发现路径** —— 核心切片一完成就做低保真入口，验证「地图—时间—作品—场景」；
3. **再做一种非地图场景** —— 检验公共数据结构是否真能支持不同类型的历史表达。

三个候选场景各验证一种表达能力：

- **卢比孔河** — 空间、边界与权限变化 ← 首个做透的场景
- **三月十五日** — 人物关系、权力结构与制度冲突
- **奥古斯都掌权** — 制度表象与实际权力的前后对比

> **这三个场景是实验样章，不是一部完整作品。** 它们是未来《共和国危机（前133—前27）》的取样，
> 可能来自不同章节，不构成对这段历史的完整讲述。界面上会明确标注出版状态。

## 设计原则（第二轮审核确立）

- **不过早模板化**：固定可信度、史料与阅读系统，保持视觉表达与作品主题的开放性。
  场景类型走 renderer registry，公共 schema 不枚举视觉类型。
- **不制造虚假精确**：底图数据支撑不到的尺度就不放大；示意内容与确证地理事实必须可区分。
- **不制造唯一答案**：有争议的解释并列呈现；不把复杂政治过程写成注定发生的结局。
- **视觉不全站统一**：全站统一的是排版、导航、间距、注释系统、来源与不确定性标记、
  交互反馈与可访问性；明暗、主色、材质、图表色彩由各作品自定。"深色展厅"只是罗马首轮的方向。

## 开发

```bash
npm install
npm run dev
```

`npm run build` 会跑两道内容校验，任一不过即构建失败。

当前主要路由：

- `/` — 真实地理上的历史世界
- `/world/rome-republic/` — 罗马卷《共和国危机》
- `/story/rubicon/` — 卢比孔全屏三幕
- `/entity/:id/` — 人物、地点、制度与文献对象页
- `/dev/scene/rubicon/` — 原有研究 / 开发视图

## 在线部署

公开站点由 GitHub Pages 托管：

`https://caelum843.github.io/history-atlas/`

`.github/workflows/deploy.yml` 会在 `main` 分支每次推送后自动构建和发布。
本地开发继续使用根路径 `/`；GitHub Actions 构建时，`astro.config.mjs` 会自动启用
`/history-atlas` base，站内路径统一通过 `src/lib/paths.ts` 生成。

## 关于 reference/

`reference/prototype_v0_raw.html` 与 `prototype_readme.md` 是 chat 窗口里的滚动叙事小实验。
它的场景数据结构和 viewBox 镜头补间思路值得参考，但海岸线是手绘示意、内容未逐条核实、
视觉是罗马专属主题，均不满足本项目要求。M1 搭起 Astro 工程时，
它的可运行副本已移入 `reference/prototype_v0_standalone.html`。
